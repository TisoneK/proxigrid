## Design decisions worth noting

- **Exits are never regime-filtered.** A position opened in an allowed regime must always be able to close; otherwise a regime shift strands it. The filter only suppresses new entries.
- **Per-asset OOS lineages.** The asset tag rides in the Backtestable spec, so the §9 ledger hashes per (spec, asset). Same params on BTC and ETH are separate validation events on different data — reusing one OOS result across assets would be exactly the single-asset dependence the critic exists to catch.
- **One bad asset ≠ failed run.** A live-fetch abort on ETH (10s client timeout) initially aborted the whole run with a 500; now the asset is skipped and reported in `assetErrors` while the rest complete. The first attempt's failure is what motivated the fix.
