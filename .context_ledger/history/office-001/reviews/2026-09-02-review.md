## Findings

### High
1. **`/api/cron/tick` publicly triggerable + timing-unsafe secret check** (fixed, cf19f41) — with `CRON_SECRET` unset the endpoint ran scan+sweep for anyone, and the `Authorization` header was compared with plain string equality. Now: fail-closed (no secret → 401 for everyone) and SHA-256-digest `timingSafeEqual` comparison. Deploy note: Vercel cron **requires** `CRON_SECRET` to be set or the cron will 401 — `.env.example` and `docs/DEPLOY-VERCEL.md` already say this.

### Medium
2. **Order route accepted garbage input; side could silently invert** (fixed, 3cc3b2d) — `side: "banana"` became SELL (`req.side === "buy" ? "BUY" : "SELL"`), quantity went through `Number()` unchecked (NaN → adapter), limit orders could omit price. Now whitelisted/validated with 400s; market orders no longer send a `price` param (Binance rejects those).
3. **No authentication on any API** (flagged, not fixed — architectural, pre-existing) — every mutation (rules CRUD, orders, watchlist, sweep) is open. Fine for the current single-user local/Vercel deployment model; becomes critical the day this is multi-user or publicly exposed. Already on the README roadmap (Auth + multi-user).
4. **Webhook actions fetch user-configured URLs with no SSRF guard** (flagged, not fixed — documented intentional in Session 7; user-configured feature, same trust boundary as the rest of the no-auth API).

### Low (all fixed this session)
5. **Unbounded `limit`/`offset`/`depth` params** → NaN/negative/huge values reached Prisma or upstream exchanges (500s, reversed windows, oversized upstream requests). New `src/lib/params.ts` `intParam` clamp applied to signals, executions, candles (1–1000 = Binance cap), orderbook (1–100). (75a7ffb)
6. **Signals POST accepted arbitrary timeframes** → adapter produced invalid upstream calls. Whitelisted with 400. (75a7ffb)
7. **Watchlist accepted any string as a "symbol"** (scanner would then try to scan junk). Now 2–32 chars, exchange-symbol charset. (75a7ffb)
8. **Dead `useTicker` hook was also broken** — appended `?symbol=` to a route that ignores it and returned `tickers[0]` of the full list. Removed (all consumers use `useTickers`). (fb79c5b)
9. **Rules `[id]` PATCH/DELETE/evaluate returned 500 for unknown ids** (P2025 leakage). Now 404 like GET. (f9701d7)
10. **Prisma client logged every SQL query** (`log: ['query']` — Session 7's "noisy in dev" note). Now errors+warnings only. (210d7af)
11. **`typescript.ignoreBuildErrors: true` masked build-time type errors**; tsc is clean, so removed — `next build` now type-checks ("Running TypeScript" confirmed in build output). (210d7af)
12. **Turbopack workspace-root ambiguity** — stray `package-lock.json` in `C:\Users\tison` made Next warn it was ignoring a lockfile outside the repo; `turbopack.root` pinned to the repo. Warning gone. (210d7af)
13. **`npm run dev`/`start` were POSIX-only** (`| tee`, `NODE_ENV=` prefix, bun) — broken under cmd.exe/npm-on-Windows. Now plain `next dev`, and `start` uses `node` + `cross-env`. (210d7af)
14. **README drift** (SQLite/bun, done roadmap items, missing endpoints). Refreshed. (dfccb4c)

## Protocol notes (this environment)

- `context-sync verify` false-fails on Windows: `core.autocrlf=true` checks core files out with CRLF so on-disk hashes can't match the LF-generated MANIFEST. Verified the core is intact (`git cat-file blob HEAD:<file> | sha256sum` matches MANIFEST for every spot-check; whole-tree failure pattern + clean pull). **Rollback intentionally not run** — it would replace a verified-intact core and risk real drift. Logged as a flaw with a suggested fix (verify against git-normalized content, or ship a `.gitattributes` with `core/ eol=lf`).
- `context-gates.ps1` crashes immediately ("Cannot bind parameter because parameter 'PathType' is specified more than once"); the `sh` edition runs fine under Git Bash on this machine, so gates were run through it.
